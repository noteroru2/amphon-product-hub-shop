# SHOP-6.3 Production Readiness Remediation

## Safety state

- `purchase_enabled=false` remains the hard guard throughout SHOP-6.3.
- No activation script was created. Activation remains a separate SHOP-6.4 owner action.
- PromptPay remains disabled and its accepted evidence state is `SKIPPED_DISABLED`.
- Document mode remains `RECEIPT_ONLY`; no automated e-Tax Invoice/e-Receipt support is implied.

## AT-TST finding

The reported `products=1, orderItems=1` was a Windows PowerShell 5.1 counting defect, not a database orphan. `Invoke-RestMethod` returned an empty `System.Object[]`; wrapping the function call with `@(...)` made that empty array one outer-array element. The raw API response was `[]`, and an exact PostgREST count returned `Content-Range: */0`.

The readiness check now inspects the test product graph and distinguishes:

- active inventory: any AT-TST product not in terminal `sold`, `returned`, or `cancelled` state;
- storefront exposure: a published website publication or an enabled/indexable listing;
- historical audit: order items retained for order/payment/document/warranty integrity.

Historical audit rows are reported but do not fail cleanup readiness. Active inventory or storefront exposure does fail readiness. No destructive cleanup was added.

## Production configuration tool

`SHOP63-CONFIGURE-PRODUCTION.bat` performs a parser check, then runs the interactive PowerShell configuration tool. The tool:

- lists required Worker secret binding names without reading values;
- requires explicit `PRODUCTION STRIPE` confirmation before setting `stripe_enabled=true`;
- asks only for missing/invalid shipping, return-policy, Turnstile public-site-key, or reservation values;
- validates the actual schema enums and numeric constraints;
- shows a masked proposed configuration;
- requires owner text confirmation `APPLY SHOP-6.3` before the single settings update;
- writes and verifies `purchase_enabled=false` in the same operation.

Turnstile's secret remains a Worker secret. The only Turnstile value stored in commerce settings is the public site key.

## Post-configuration acceptance invalidation

The owner configuration was written successfully, with `purchase_enabled=false`. The production Worker now reports Stripe, shipping, return policy, and Turnstile readiness enabled with the intended values.

SHOP-6.2's `commerce_store_settings_shop62_invalidate` database trigger intentionally clears `shop62_acceptance_version`, `shop62_accepted_at`, and `shop62_acceptance_evidence` whenever critical payment or fulfillment settings change. Therefore the SHOP-6.3 write invalidated the earlier provider evidence even though the client PATCH did not include or overwrite those fields. This is a safety gate, not data corruption; evidence must be regenerated by the isolated Provider E2E against the final configuration and must never be fabricated.

The final checker now handles missing, null, JSON-string, hashtable, and PSCustomObject evidence under StrictMode. Missing keys produce `FAIL / MISSING` instead of terminating the script.

## Read-only final readiness check

`SHOP62-FINAL-ACTIVATION-CHECK.bat` remains read-only and now reports `SHOP-6.3 FINAL ACTIVATION READINESS`. All web requests use PowerShell 5.1 `-UseBasicParsing`, so no Internet Explorer parsing prompt is possible.

## Operator sequence

1. Run `SHOP63-CONFIGURE-PRODUCTION.bat` and supply owner policy values.
2. Run `SHOP62-FINAL-ACTIVATION-CHECK.bat`.
3. Stop after `SHOP-6.3 FINAL ACTIVATION READINESS: PASS`; do not activate checkout in this phase.

Patch versions and conditions were verified against the primary
[glob advisory](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4) and

**Reachability assessment before patching (source-based inference):** these were
Node build dependencies, not the publisher Worker or browser runtime. Workbox's
`get-file-details.js` calls `globSync` without an AbortSignal, so the reported
abort-budget failure was not exercised by that call. Glob did use minimatch
optimization level 2, but this repository supplies fixed build patterns; no
customer record, uploaded image, queue request or HTTP parameter was found to
control them. An attacker editing build configuration could reach build-time DoS,
but that trust boundary already permits running Node build code. No remotely
exploitable customer-input path was demonstrated. This limited reachability was
not used to waive the audit or suppress findings.

**Fix:** a narrow, exact npm override, confined to the Workbox dependency subtree:

```json
{"overrides":{"workbox-build":{"glob":{".":"14.0.2","minimatch":"11.0.1"}}}}
```

This deliberately crosses the leaf packages' major-version ranges; it is not
described as an upstream semver-compatible update. Compatibility for the APIs
used by this app was demonstrated by actual Workbox manifest enumeration,
ignore/size/hash checks, cancellation and bounded pattern tests, a clean locked
install, and the complete PWA build. No plugin downgrade, audit exclusion,
`--omit=dev`, forced PWA upgrade or handwritten node_modules patch was used.
The unrelated `minimatch@5.1.9` under Workbox's ejs/jake/filelist chain is outside
this advisory's affected range and remains unchanged.

**Current audit: PASS, exit 0, zero vulnerabilities across all severities.** There
are no unresolved known npm findings in this audit, so no remaining Moderate
waiver is requested. Keep the override and lockfile until a reviewed upstream
parent supports the fixed leaf versions; remove it only with the same tests.
Additional mitigations remain fixed trusted build patterns, no Production secrets
in QA jobs, disabled checkout credential persistence, and 20-minute build /
10-minute SQL job timeouts. These do not claim to sandbox arbitrary hostile code.
Linux hosted CI at the eventual approved head is still a release gate; local

### Security behavior improved and tested

- **Private staging:** capture the entire approved snapshot before download,
  compare it immediately before PUT, then validate it again after PUT. A valid
  but changed source path or consent timestamp also fails. Revocation, deleted
  rows, inactive Owner or unavailable post-write database no longer produce a
  successful stage receipt. Lost PUT responses produce a sanitized uncertain-write
  reconciliation error; there is no automatic retry within that invocation.
- **Draft PRs:** retain pre-mutation checks, add a post-PR check before recording
  success, and sanitize uncertain mutation / failed receipt errors. A cancellation
  during PR creation does not overwrite CANCELLED with a successful receipt.
  Existing branches block duplicate retries after an orphan PR/receipt failure.
- **Shared media:** in-flight synthetic tests prove an object can already exist
  despite a failed post-check. No automatic deletion was added. A second site's
  active reference can share the same key, so deleting it would be unsafe.
- **Retention review:** new `scripts/evidence-retention-review.mjs` is an offline,
  read-only classifier, with no CLI, network, secrets or delete implementation.
  It hashes output keys and always returns `deletion_authorized:false`. Tests
  cover active shared references including RELEASED, unknown states, incomplete
  inventory, recent writes/cancellations, old orphans and expired cancelled objects.
  Current queue rows lack `cancelled_at`; missing timestamps hold the object.
- **Browser retention defect:** `vite.config.ts` previously cached every image
  for seven days. It now places a self-contained private/signed/authorized image
  NetworkOnly/no-store match before public product-image CacheFirst. New
  `public/evidence-cache-cleanup.js` removes matching historical entries on SW
  activation while retaining ordinary public product images. The actual generated
  SW was evaluated against inert Workbox stubs: callback serialization, route
  ordering, no-store, cleanup import/precache and copied cleanup source all passed.
  These changes are local only; no browser cache or deployed service was changed.

The fuller recovery/retention specification is in
[the updated retention review](EVIDENCE_PUBLISHER_PRIVATE_RETENTION_REVIEW.md).
The owner-only offline backup procedure was read and remains unchanged; no
customer backup or real media was accessed.
